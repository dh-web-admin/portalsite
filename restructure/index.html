Migration sequence

Ordered so each step makes the next one safer. Steps 1–3 are reversible and touch few files; step 7 is the only one that changes public URLs.

  1. Dead code removalyou are here → next Two (old) engineering files, a .bak, three stray .log files, and the request-logging block at the top of api/update_bid.php. ~6,200 lines git already remembers.
  2. Composer autoload + src/ PSR-4 App\ → src/, plus bootstrap.php with ob_start() and a role resolved once per request.
  3. Build layouts/portal.php, migrate one page Prove the template on employee_information (474 lines) before touching anything large.
  4. Roll the layout across all pages Delete the redundant auth block from each as you go — access_gate.php already ran it.
  5. Split JS and CSS out of the pages Largest first: Bid_tracking, scheduling, maps. Mechanical once page_data exists.
  6. config/pages.php manifest One declaration read by the dashboard, sidebar and permissions instead of five edit sites.
  7. Per-page api/ folders One page at a time — this changes endpoint URLs, so every fetch() moves with it.
  8. Naming cleanup One rename commit at the end: Bid_tracking → bid_tracking, whishlist → wishlist, all_warrenties → all_warranties.

Decisions behind the tree

Pages keep view.php, not index.php

A directory-index filename invites the server to serve it; naming it view.php makes it explicit that the layout renders it, and keeps the /pages/<key>/ URL shape that access_gate.php parses. Directory URLs keep working through DirectoryIndex.

No page implements its own auth

access_gate.php already runs the login check, permission check and account-lock check before any page code executes. The ~30-line auth block copied into 68 files is redundant, not merely duplicated — deleting it is step 4, one page at a time.

Two copies of fetch_equipment_filters.php

One in api/, one in pages/equipments/, with different contents. Reconcile them into a single file before the equipments page moves, or the merge silently picks a winner.

Step 7 changes public URLs

There is no router — physical paths are URLs. Moving an endpoint moves its URL, so every fetch() that names it has to move in the same commit. This is why it is one page at a time and why it comes last but one.

Nineteen endpoints have no caller

Marked ? in the tree. Some are genuinely dead; others were reached from the two (old) engineering files through a computed apiBase + '/name.php', so deleting those files in step 1 truly orphans them. Decide each one deliberately rather than moving dead code into a tidier folder.

This folder is served without authentication

.htaccess gates PHP, not static HTML, so this page is readable by anyone who can reach the host. Add restructure/ to the deny rules before deploying, or keep it local.
